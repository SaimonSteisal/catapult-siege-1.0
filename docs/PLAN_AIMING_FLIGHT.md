# PLAN: Наведение и полёт снарядов 2.0 (v1, раунд 1.5.0)

Статус: **ПЛАН — не реализовано**. Продолжение традиции `PLAN_UNITS_AND_FORTS.md`.
Требования заказчика: удобство **без лишних окон**, точность, дуга **корректно показывает
точку падения/детонации** для взрывных и картечи (и для остальных, где логично).

## 0. Аудит: разрывы «дуга ↔ факт» и боли управления (факты по коду)

### 0.1. Баллистика говорит одно, снаряд делает другое
| # | Факт | Где | Последствие |
|---|---|---|---|
| B1 | `predict()` останавливается на **первом контакте** (terrain/block) | `physics.js:154-183` | для взрывных дуга показывает контакт, а не детонацию; для взрывателя 0.4 c («Разрывное») снаряд после контакта ещё летит с `vel*0.35` и рвётся **за** стеной — дуга врёт на целый двор |
| B2 | Взрыватель = **реальный** `setTimeout(fuse*1000)` | `ballistics.js:104` | взрыв происходит даже на паузе/в настройках/при timeFreeze во время наводки; предикт не может зеркалить реальное время |
| B3 | Взрывные/картечь/улей/зажигательное на **земле** не детонируют: `_detonateOrImpact` рисует лишь пыль | `ballistics.js` `_onHit→terrain` | картечь по пехоте в поле = пустышка; дуга обещает кольцо, факт — «miss» |
| B4 | Предикт интегрирует с **постоянным** ветром (`this.wind`) | `physics.js:192` | порывы (`updateWind(t)`) за 3–5 c полёта уводят снаряд на метры относительно дуги в windy/gale-миссиях |
| B5 | Рикошет камня/гранита (restitution 0.28/0.18) в бою есть, в предикте нет | `physics.js:135-143` vs predict | снаряд после отскока бьёт дальше, дуга обрывается на первой точке |
| B6 | Anchor-пробитие: в бою до 3 continued-полётов (`vel*0.62`), в дуге — одна точка | `ballistics.js` pierce | «пробивает насквозь» не показано куда выйдет |
| B7 | CEP-диск семплируется точками **контакта**, а не детонации | `main._sampleSpread` | для взрывных область «куда может попасть» смещена от реальных центров взрывов |
| B8 | Солвер `_solveAim` скорит по точке контакта | `main.js` | для «Разрывного» авто-наводка целится контактом в стену, а не взрывом за неё — авто-совет саботирует ammo-специализацию |

### 0.2. Боли управления
| # | Факт | Где | Последствие |
|---|---|---|---|
| U1 | Мощность = **радиус драга** (`a0.power + dist*powerPerPx`) — связана с dx/dy | `hud.js aimmove` | любое движение азимута/высоты непредсказуемо меняет мощность; точная правка = борьба с собственным пальцем |
| U2 | «Точный» = **отдельное окно** с 3 слайдерами | `hud.js precPanel` | то самое «лишнее окно»: перекрывает пол-экрана, рвёт поток «вижу цель → стреляю» |
| U3 | Автопоправка после промаха **молча меняет прицел игрока** | `main._correctionHint` (при aimAssist) | ощущение, что игра стреляет сама; конфликтует с «точностью руками» |
| U4 | Тап по цели только выбирает её (+камера), но **не наводит** | `main._onViewportTap` | игрок сам должен повторять решение солвера, который уже есть в коде |
| U5 | Нет времени полёта/радиуса в точке: маркер — безмолвный крест | `vfx.showPrediction` | для взрывных непонятно, накроет ли кольцо цель |

## 1. Цели / не-цели
**Цели:** (1) единый источник правды полёта (predict == live); (2) дуга заканчивается
**точкой детонации** с кольцом радиуса для взрывных/картечи/огня/улья, отскоком для
камня/гранита, выходом для anchor; (3) наведение одним пальцем без окон: стик +
power-полоса + fine-режим вторым пальцем + tap-to-solve; (4) ветер предикта = ветер полёта.
**Не-цели:** физика деформации, баллистика с вращением (Магнус), ручная таблица поправок,
полный отказ от кнопки «ОГОНЬ».

---

## 2. Единые правила полёта (FlightRules) — новый модуль `src/systems/flightRules.js`
Одна таблица поведения снаряда, которую читают **и** предикт, **и** боевой `_onHit`:
```js
rulesFor(ammoId, modsFlags) → {
  terrainDetonate: radius > 0,            // B3: взрывные рвут и о землю
  fuseSec: ammo.fuse || 0,                // B2: взрыватель в ИГРОВОМ времени
  fuseVelMul: 0.35,                       // скорость после контакта (зеркало боя)
  pierce: ammo.pierce ? { max: 3, velMul: 0.62, keGate: 3 } : null,   // B6
  bounce: restitution >= 0.15 ? { e: restitution, friction: 0.5, max: 1 } : null, // B5
  blastRadius: base R + stoneRain/demolitionist (из mods.flags),      // кольцо
}
```
- **B2 фикс:** `p.fuseT` тикает в `ballistics.update(dt)` (игровое время, пауза честна);
  setTimeout убирается.
- **B3 фикс:** terrain-контакт radius-снаряда → `_detonate` (урон, солдаты, поджог).
- Предикт и бой расходятся только в случайном спрэде при запуске (честно, показан CEP).

## 3. `predictFull()` — дуга как правда
Расширение `physics.predict` (или обёртка в ballistics):
1. Интегрирование с **эволюцией ветра**: новый `physics.windVecAt(t, out)` (формула из
   `updateWind`, чисто по t — уже есть прецедент `windAt(t)` из 1.2.2) → B4 закрыт.
2. Первый контакт → ветвление по FlightRules:
   - fuse: продолжить интегратор с `vel*0.35` на fuseSec (dt 0.03) → точка детонации;
   - radius без fuse: детонация в контакте (включая землю);
   - pierce: до 3 продолжений `vel*0.62` (предикт предполагает пробитие, если
     ke-оценка > гейт; иначе стоп) → цепочка точек входа/выхода;
   - bounce: одно отражение `v' = v − (1+e)(v·n)n`, тангенс ×friction → доп. дуга 1.2 c.
3. Возврат: `{ pts, contact, detonation, radius, tof, bouncePts[], piercePts[] }`.
4. CEP: `_sampleSpread` семплирует **detonation-точки** (B7); диск = их разброс.
5. Солвер `_solveAim` скорит по **detonation** (B8): «Разрывное» учится навесу за стену,
   картечь — площади по двору; контакт-скоринг остаётся только для pierce/stone.

## 4. Рендер дуги (vfx + HUD, без окон)
- Линия: основная до контакта; для fuse/pierce/bounce — **призрачное продолжение**
  (opacity 0.35) до детонации/выхода/отскока.
- Маркер детонации: крест + **кольцо радиуса взрыва** на земле (реальный R с учётом
   синергий), цвет по типу снаряда (boom=оранж, shrapnel=сталь, fire=огонь, hive=улей).
- Земля-детонация (B3) рисует то же кольцо — игрок видит зону по пехоте.
- Мировая плашка у маркера (как target bar, не окно): `62 м · 3.4 c · R 3.2 м`
  (дистанция, TOF, радиус; для stone/granite — `↩ отскок`-иконка, когда bounce-ветка есть).
- CEP-диск/кольцо/точки семплов — как сейчас, но центрированы по детонации.
- `hidePrediction`/тумблер «Предиктивная дуга» сохраняются.

## 5. Пульт наводки: один пад, ноль окон
Схема (`#aimpad`, всё внутри существующей панели):
```
┌───────────────────────────────┐
│  STICK-ZONE (аз/выс)          │  ← драг = азимут/возвышение (как сейчас,
│   ◎ knob                      │    но БЕЗ радиальной мощности, U1 фикс)
│                               │
├──╌╌ CANCEL (слева внизу, как сейчас) ──┤
│  POWER-ПОЛОСА [30%██████░░100%]│  ← горизонтальный драг = мощность (абсолют
└───────────────────────────────┘    по x полосы), цифра % тут же на полосе
```
- **Power-полоса**: высота ~20% пада, градиент + риска текущего значения; жест в полосе
  НЕ стреляет при отпускании (коммит мощности); жест в стик-зоне при отпускании стреляет
  (как сейчас); cancel-зона переезжает в левый край полосы (радиус тот же, `_syncZones`
  пересчитывает центр из новой геометрии).
- **Fine-режим**: второй палец на паде → множитель чувствительности ×0.25 для обоих
  пальцев (индикатор: рамка пада светится золотом); U2-замена слайдерам 0.5°.
- **Tap-to-solve**: тап по цели в вьюпорте = выбор + мгновенный `_solveAim` текущим
  снарядом по детонации (U4); повторный тап по своей же цели = снять выделение.
  Входит в тумблер «Помощь в наводке» (aimAssist).
- **Автопоправка (U3)**: вынесена в отдельный тумблер `autoCorrect`, **default OFF**;
  при OFF после промаха показываются только подсказки-плашки («недолёт 4 м») и
  призрачный маркер предложенной поправки на дуге — прицел не трогается.
- **Удаляется**: `precPanel`, `precBtn`, настройка `precisionAim` (миграция: ключ
  игнорируется, reconcile докинет `autoCorrect:false`), строка «Точный» в тулбаре.
- Клавиатура: стрелки = аз/выс, Q/E = мощность (полоса), Shift = ×0.25, пробел = огонь.
- Readout-чипы AZ/EL/PWR/CEP остаются на паде (это не окно, это приборная строка).

## 6. Настройки (диф)
- убрать «Точное прицеливание»;
- добавить «Автопоправка после промаха» (`autoCorrect`, default false);
- «Помощь в наводке» теперь = подсказки + CEP + tap-to-solve (подпись уточняется).

## 8. Производительность
- predictFull: +≤ fuse/dt2 (~14 шагов) + bounce (~20) на один проход; CEP 8 семплов ×
  то же; на `low`-качестве CEP-семплы 4, bounce-ветка не рисуется.
- `_updatePrediction` уже троттлинг (aim-change + 0.25 c) — сохраняем.
- windVecAt(t) — 2 sin/noise-вызова, дёшево.

## 9. Тест-план
- **headless (unit+)**: MIRROR-тест по каждому снаряду: спред=0, ветер calm → боевая
  точка детонации == predictFull.detonation в пределах 0.4 м; fuse на паузе НЕ взрывается
  (game-time); взрывное о землю даёт blast-урон блокам в R; картечь по земле косит
  солдат; anchor-предикт показывает ≥2 точки при ke>гейта; bounce-точка камня совпадает
  с боевым отскоком ±0.5 м.
- **graphics-check**: power-полоса меняет только мощность (az/el неизменны); стик-драг
  не меняет мощность (U1-фикс); fine-режим ×0.25 измеримо; tap-to-solve кладёт детонацию
  в ≤2 м от центра цели; `#hud .precPanel` отсутствует в DOM; плашка `м · c · R` видна.
- **button-audit**: тулбар 5 кнопок (без «Точный»), cancel-зона на новом месте работает
  (регресс E2E-ассерта отмены), «ОГОНЬ» и тап-сольв живут вместе.
- **E2E (test-browser)**: старый touch-aim ассерт переписан под новые зоны
  (стик = az/el, полоса = power), отмена в cancel-зоне сохраняется.
- **balance-report**: солвер на детонации может поднять pass-rate взрывных — контроль
  ±3% по главам, иначе правка `rankThresholds` НЕ трогается (только ammo-числа).

## 10. Этапы
- **A1 «Правда полёта»**: FlightRules, game-time fuse, terrain-детонация, windVecAt в
  предикте, predictFull, солвер по детонации. Приёмка: mirror-тесты зелёные.
- **A2 «Честная дуга»**: рендер продолжений/колец/плашки, CEP по детонации, цвета по
  типам снарядов. Приёмка: скриншоты по 8 снарядам, плашка и кольцо видны.
- **A3 «Пульт без окон»**: зоны пада, power-полоса, fine, tap-to-solve, удаление
  precPanel/precisionAim, autoCorrect-тумблер, клавиатура, `_syncZones` для новой
  cancel-геометрии (левша-зеркало учитывается!). Приёмка: button-audit + E2E зелёные.
- **A4 «Упаковка»**: i18n, DEVLOG 1.5.0, versionCode 6, регенерация zip/patch/preview,
  прогон всех сьюит + balance.

## 11. Риски
| Риск | Митигация |
|---|---|
| Смена feel пада раздражает muscle-memory | стик-зона сохраняет прежнюю математику аз/выс; мощность просто переезжает в полосу; «ОГОНЬ» на месте |
